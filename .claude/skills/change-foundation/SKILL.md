# Change a design-system foundation

Deterministic workflow for editing tokens in this repo. The single source of
truth is `packages/<pkg>/src/foundations.ts` (typed as `ProductFoundations`
from `@zytedata/ds-types`); `tokens-build` compiles it into `dist/` artefacts.

## Products (slug → package)

| slug | package | filter |
|------|---------|--------|
| `core` | `@zytedata/ds-core` | `packages/core` |
| `web` | `@zytedata/ds-web` | `packages/web` |
| `scrapy` | `@zytedata/ds-scrapy` | `packages/scrapy` |
| `extract-summit` | `@zytedata/ds-extract-summit` | `packages/extract-summit` |

Pick the product from the request. If ambiguous (the change could apply to
several), ask which product(s). A change can target more than one — repeat the
steps per package.

## Steps

Run every command from the repo root.

### 1. Edit `packages/<pkg>/src/foundations.ts`
- Make ONLY the requested change. Do not touch unrelated token groups
  (e.g. leave typography and Tailwind-shaped scales alone unless asked).
- Keep the `ProductFoundations` shape. Colors are
  `Record<paletteName, Record<shade, hex>>`; use `DEFAULT` for a single-value
  palette (it emits the bare `--<slug>-<palette>` var). `semanticColors` maps a
  role to a **palette name** (e.g. `brand: "accentSecondaryCold"`).
- Never edit anything under `dist/` — it is generated.

### 2. Update prose in `packages/<pkg>/src/design.body.md` (if semantics changed)
- Edit only the human-readable `design.body.md`. Its YAML front-matter is
  regenerated by the build — never hand-edit `dist/design.md`.
- Update the relevant section (Colors / Typography / …) so the prose matches
  the new tokens. Skip if the change is a pure value tweak with no semantic
  shift.

### 3. Build to `dist/`
```bash
pnpm --filter "@zytedata/ds-<slug>" run build      # build:js (tsc) → build:tokens
```

### 4. Verify
```bash
pnpm --filter "@zytedata/ds-<slug>" run check:tokens
pnpm --filter "@zytedata/ds-<slug>" run typecheck
```
Then confirm the change actually emitted — grep the new token in the output,
e.g.:
```bash
grep -n "<changed-var-or-value>" packages/<pkg>/dist/tokens.css
```
If any step fails, fix and re-run before continuing.

### 5. Changelog — BOTH mechanisms

**a) `packages/<pkg>/src/changelog.ts`** — append an entry to the block whose
`file` matches what you changed (`"foundations.ts"` for token changes; add a
`"design.body.md"` entry too if you changed prose). Newest entry first.
- `date`: today's date — get it with `date +%F` (do not hardcode).
- `author`: the git user's short handle — `git config user.name` (match the
  style of existing entries, e.g. first name).
- `kind`: `added` | `changed` | `removed` | `fixed`.
- `message`: one concise sentence describing the change.

**b) Changeset** — write `.changeset/<short-kebab-summary>.md` directly (do not
run the interactive `pnpm changeset`):
```md
---
"@zytedata/ds-<slug>": minor
---

<one-line summary of the change>
```
Bump level: `minor` for added / renamed / restructured tokens, `patch` for a
value-only fix. List multiple packages on their own lines if the change spans
products.

### 6. Figma plugin sync — ASK FIRST
Color changes can also be mirrored into the Figma plugin so it populates the
new values on fetch. **Ask the user whether to do this** before touching it.
If yes:
- `figma-plugin/` is gitignored / local-only and hand-maintained.
- For **core/scrapy/extract-summit**: edit the matching `*_COLORS` object (and
  `semanticColors`) in `figma-plugin/code.js` to match `foundations.ts`, then
  `node --check figma-plugin/code.js`.
- For **web**: it is generated — run
  `node figma-plugin/scripts/gen-foundations.js` (reads
  `packages/web/dist/tokens.json`, so build web first).
- Reloading the plugin in Figma is a manual user step.

### 7. Stop and report — do NOT commit
Leave all changes in the working tree for review. Summarize:
- which `foundations.ts` tokens changed (old → new),
- the emitted `--<slug>-*` vars/values that confirm it,
- verification results (build / check:tokens / typecheck),
- the changelog.ts entry and changeset file added,
- whether the Figma plugin was synced.

Do not branch, commit, or push. Mention the user can ask to commit/PR as a
separate step. Note that `dist/` artefacts are gitignored (generated), so the
committable files are `foundations.ts`, `design.body.md`, `changelog.ts`, and
the `.changeset/*.md`.
