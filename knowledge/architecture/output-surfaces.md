# The output surfaces (dist artefacts)

## What it is

Every product package emits one shape of tokens per consumer stack. Consumers
never see `src/`; they import from `dist/` via the package's `exports` map. This
doc is the reference for what each surface is.

## The pieces

Per `packages/<slug>/dist/` (generated by [codegen-engine.md](./codegen-engine.md)):

| Artefact | Export path | Shape / consumer |
|----------|-------------|------------------|
| `tokens.css` | `@zytedata/ds-<slug>/tokens.css` | `:root { --<slug>-*: … }` CSS custom properties. Works anywhere; namespaced per product so multiple products coexist. |
| `tokens.scss` | `@zytedata/ds-<slug>/tokens.scss` | `$<slug>-*` SCSS variables (comma/space values quoted). |
| `tokens.tailwind.cjs` | `@zytedata/ds-<slug>/tailwind` | A Tailwind **v3 preset** — colors nested under `colors.<slug>.*`, other scales flat as `<slug>-*`. Values are `var(--<slug>-*)`, so consumers must also import `tokens.css`. |
| `tokens.json` | `@zytedata/ds-<slug>/tokens.json` | DTCG-flavoured JSON (`$product/$label/$version`, `$value`/`$type` per leaf, `semantic.color`, `components`). Consumed by tooling and by the Figma plugin generator. |
| `design.md` | `@zytedata/ds-<slug>/design.md` | The machine-readable spec: generated YAML frontmatter (full token set + branding) + the `design.body.md` prose. The LLM/agent surface. |
| `foundations.js` / `.d.ts` | `@zytedata/ds-<slug>/foundations` and `.` | The typed foundations object (`<SLUG>_FOUNDATIONS`) + the barrel of `changelog`, `documentation`, `branding`, etc. |
| `templates/<id>.{md,html}` | (Web only, via `assets`/route) | Self-contained use-case specs (`marketing`, `report`, `deck`) — base layer + overlay flattened into one file. |

Web additionally exports non-token assets: `./assets/*`, `./fonts.css`
(`Yellix`), `./fonts/*` — served straight from `src/assets/`, not generated.

## The contract

- **`tokens.tailwind.cjs` is a v3 preset.** It relies on Tailwind v3's
  `flattenColorPalette` to expand `colors.<slug>.*` into utilities; non-color
  scales are pre-flattened because v3 only deep-flattens colors. Consumers on
  Tailwind v3 add it under `presets: [...]` **and** import `tokens.css`.
  (Note: the dashboard itself uses Tailwind **v4** with a CSS-first `@theme`
  setup and does **not** consume these presets — see
  [dashboard-runtime.md](./dashboard-runtime.md).)
- **Validated by `tokens:check`** (`checkPackage` in `tokens-build`): each of
  `tokens.json/css/scss/tailwind.cjs/design.md` must exist and be non-empty;
  `tokens.json.$product === slug`; `tokens.css` contains `--<slug>-`;
  `design.md` frontmatter declares `product: "<slug>"`. That's the full extent of
  the automated check — value correctness is not verified.
- **`design.md` has no source-fallback in the dashboard.** The dashboard reads
  `dist/design.md` only; if the build didn't run, the page shows "missing"
  rather than stale `design.body.md`.

## Gotchas

- Hand-editing any of these is pointless — regenerated every build, git-ignored.
- The Tailwind preset's values are CSS vars; forgetting to also import
  `tokens.css` yields utilities that resolve to nothing (a classic consumer bug,
  called out in the README troubleshooting).
- `design.md` frontmatter is generated by a hand-rolled YAML dumper, not a
  library — if you add an exotic value type to foundations, eyeball the emitted
  frontmatter.
